3. Rendering Pipeline
Backend: ezdxf.addons.drawing.matplotlib.MatplotlibBackend — true vector rendering
Resolution: 200 DPI at 30″×22″ → 6000×4400 px PNG (confirmed in smoke test)
Coordinate transform: linear DXF model-space ↔ pixel map (CoordTransform.dxf_to_pixel)
Smoke test result: Benchmark Set 2 DXF rendered in ~30 s, 197 KB output, DXF extents correctly captured
4. Beam Cropping Strategy
Source: BeamAxis.json (R.3) → dxf_centroid_x/y ± beam_length_mm/2
Fallback: beam_registry.json → centroid_x/y + clear_span_mm
Padding: configurable, default 3 000 mm (3 m) around beam on all sides
Ensures leaders, annotations, support zones, stirrup callouts are never clipped
PIL Image.crop() with Y-axis flip correction

6. Metadata Schema
Each Beam_<ID>_meta.json contains: beam_id, beam_mark, drawing_file, dxf_source, image_file, beam_dimensions (width/depth/span mm), beam_orientation, bbox_dxf, bbox_pixels, image_size_pixels, annotation_count, roles_discovered, diameters_mm, stirrup_present, engineering_phases, generation_timestamp, model_version.

Every expected beam has an image
Every image has a JSON
Every JSON references a valid beam ID
No duplicate beam IDs
No orphan annotations (missing annotation_id)
No missing metadata files
No empty image files (0 bytes)
